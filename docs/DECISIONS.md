# 架构决策

## 2026-10-17：独立 Rust MVP 管理程序

用户目标是减少每次安装 / 更新的依赖下载，已明确授权开分支移植现有 MVP。

采用 Rust 编译产物承载管理逻辑、TUI 和生命周期；Mihomo 保持独立。保持 JSON manifest 和内容寻址的 provider 缓存兼容，以支持迁移。核心仅在缺失或版本变化时下载。

较简单的替代方案是复用系统 Python，或缓存现有 Python 发行包；前者引入目标机器版本依赖，后者仍需分发解释器。Rust 更符合本次减少目标机器依赖的要求。

保留当前源码及所有预先存在的未提交修改，在 `rust/` 中实现独立发行路径；不自动发布、不覆盖服务器上的已有安装。

### 分发与迁移边界

管理程序以不含解释器和代理核心的薄包分发。Mihomo 使用内置校验和固定为 v1.19.29；相同版本可复用本地文件，应用升级保留该文件。首个已验证产物为 Linux x86_64 GNU，依赖系统 glibc / libgcc；musl 和 ARM64 在实机测试之前不宣称兼容。

Rust 使用独立安装标记，通过显式 `--import-data` 读取旧 MVP 的状态和缓存，避免旧 Python 升级器把 Rust 包当成 Python 包。在线发行源须使用专用 Rust 元数据，现有 Python 发行源不复用。

继承原工作台的交互合约和每操作一个工作进程的取消边界，先确保行为可对照；不为减少进程数量牺牲事务完成 / 回退语义。核心生命周期改为 Rust，目标机器无需 curl、Python 或 ncurses 才能执行核心管理。

## 2026-10-17：订阅维护与备份

用户要求修复单订阅无法删除，并增加订阅自动更新和配置备份。删除当前订阅时切换到剩余第一项；最后一项删除后停止核心并清除托管配置，沿用事务日志恢复。

自动更新采用当前用户的 cron 运行短命令，每 5 分钟检查可配置的更新间隔，默认关闭。相比常驻 Rust 守护进程，复用系统调度器使运行状态和生命周期更简单；cron 是此可选功能的系统前提，不增加 Rust 库依赖或解释器下载。注册仅改写本安装拥有的标记块，保留其他任务。

配置快照包含订阅、选择、模式、控制密钥和引用缓存，保存为 0600 的 tar.gz；恢复先创建当前快照，再执行既有事务流程。恢复不改动监听端口或注册系统任务。密钥变化不能依赖 Mihomo 热重载，必须在事务中重启核心，失败时恢复原配置与运行状态。

## 2026-10-17：收敛为唯一 Rust 应用

用户明确要求仅保留 Rust 版本。删除旧 Python / Shell 应用、旧测试与发布流程，以及 Dashboard、subconverter、旧核心与重复校验文件；保留 Rust 使用的 shell 集成模板、Python 维护工具、核心固定校验和及许可证。

采用最小清理方案，继续使用 `rust/`，避免将源码移动到根目录所需的构建路径与开发数据目录改动。旧应用的未提交源码已在仓库外保存恢复快照，历史验证记录和可能含用户数据的旧 runtime 文件也移到仓库外；可重新生成的旧下载缓存直接移除。Git 历史不改写。

删除测试中可选的 Python MVP 双实现对照分支，保留同一真实流量场景与独立行为断言。将原 TUI 模块中的公共显示与错误脱敏函数移入 `output.rs`，让 CLI、文本菜单、维护任务与 TUI 共用它们，消除业务模块对 TUI 的反向依赖。未引入库或其他抽象。安装 / 升级、订阅事务及 TUI 暂不按行数拆分，避免无行为收益的结构变更。

## 2026-10-17 · CI 对齐 GNU 发行目标

首次公开 Rust 源码的 Actions 运行 `39010627500` 中，x86_64 musl 包编译成功，但执行核心安装时以 SIGSEGV（139）退出；ARM job 被矩阵 fail-fast 取消。该静态目标尚无已通过的实机运行证据，也未作为本次公开安装包。
